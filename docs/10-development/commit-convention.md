# Commit Convention

## Message format
- Use a short, descriptive subject line.
- Keep the subject line in the imperative mood.
- Use a blank line before additional details when needed.

## Subject guidelines
- Start with a verb such as add, update, refactor, fix, remove, or document.
- Keep the subject concise and specific.
- Prefer meaningful scope hints when they improve clarity.

## Body guidelines
- Explain why the change was needed.
- Mention architecture, business rule, or documentation impact when relevant.
- Avoid unnecessary detail or implementation noise.

## Examples
- `add modular monolith folder scaffolding`
- `document environment configuration placeholders`
- `refine coding standards for module boundaries`
- `fix formatting guidance for development docs`

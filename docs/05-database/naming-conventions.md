# Naming Conventions

## Tables
- Use singular, business-oriented table names where practical.
- Prefer lowercase snake_case for table names.
- Use names that reflect the business concept rather than the implementation detail.

## Columns
- Use lowercase snake_case for column names.
- Prefer descriptive names that explain the meaning of the field.
- Use common conventions such as id, code, name, status, and created_at.

## Indexes
- Use names that describe the indexed concept and the columns involved.
- Prefer consistent prefixes such as idx_ when the database tooling requires explicit naming.

## Constraints
- Use clear names that describe the rule being enforced.
- Keep constraint names predictable and understandable during troubleshooting.

## Foreign keys
- Use names that indicate the related table and the relationship purpose.
- Prefer explicit naming over autogenerated names when the convention is important for maintainability.

## Junction tables
- Use names that reflect the two related entities and the relationship they form.
- Keep junction table names simple and unambiguous.

## Enums
- Use uppercase snake_case names for enum types.
- Use uppercase snake_case values when the platform needs explicit enumerated states.

## Views (future)
- Use descriptive names that indicate the business purpose of the view.
- Keep view naming consistent with the underlying domain concept.
